# 如约 使用说明

如约 1.4.3 是实验半成品，2026-09-30 起暂停迭代。请先按[开发指南](development.md)启动服务，两位使用者连接同一服务；仅使用合成测试资料。当前流程使用单一进度记录，奖励由兑现方标记后结束。验证范围见[测试指南](testing.md)。

## 先建立关系

各自注册账号，设置自己的昵称。一方在“我们”页创建亲子、情侣或自定义关系，将邀请口令私下交给对方；对方加入后才能提出约定。邀请过期可重新生成。自己的关系称呼可以修改，不会改写对方身份。

孩子没有自己的账号时，选择家长代记，填写孩子称呼。该模式由家长记录，不把家长操作显示为孩子独立同意。孩子有独立账号时使用双方协作关系。

## 找到现在要做的事

日常页按关系分组列出待跟进约定，显示成员，以及“待我完成”“等待对方验收”等下一步。点击整行查看详情；右上方“创建约定”发起新约定，下方“查看全部约定”进入完整列表。约定与奖励页同样按关系分组，组头显示成员和数量，避免把不同关系的记录混排。

默认查看全部关系。拥有多段关系或已有范围选择时，“我们”页操作区会显示“查看范围”。点击后选择关系，再点“应用范围”，日常、约定、奖励和我们四页会共同使用该范围；点击“返回”取消本次选择。选中的关系会在操作区下方提示，再次进入“查看范围”可恢复“全部关系”。关系卡右上角的“关系操作”菜单提供修改称呼、邀请操作和解除关系，解除仍需确认。

约定页和奖励页可以通过“筛选状态”下拉框查看对应记录；奖励页选项为全部、待兑现和已兑现，行内用“我兑现 · 对方获得”或“对方兑现 · 我获得”说明角色。主流程为待接受、待完成、待验收、待兑现、已兑现；草稿、拒绝、取消和到期另行显示。解除关系后，已经产生的奖励仍会保留。列表中的整行及箭头都是查看入口；详情从顶部打开，查看当前动作、进度记录、条款与奖励。点击“返回列表”回到刚才浏览的位置。顶部同步信息只在同步中或有反馈时出现。

## 把约定说清楚

选择“创建约定”，分三步填写：先选已建立的关系并说清标题、达成条件、次数和截止，再填写奖励与兑现天数，最后核对完整条款及双方角色。提出者负责验收与奖励兑现，关系中的另一位负责执行；想交换角色时由对方发起新的约定。一次性事项目标次数为 1；累计目标填写总次数。完成截止可以不限期。上一步会保留输入；在最后一步可“存为草稿”或“发出约定”。发出后需等对方接受，对方也可以拒绝。

对方接受后，执行者记录进度，填写本次数量并按需附说明或照片；完成时添加说明或照片并提交。累计目标先完成全部次数，再统一提交验收。照片只供此约定有权成员查看。

详情中的“进度记录”统一呈现创建、接受、每次进度及说明/照片、提交、验收、兑现与后续变更，不再分成进度和事件两份列表。记录会标明时间、操作人及家长代记来源。独立“留下说明”入口已移除，旧说明和历史照片继续保留。

## 验收与奖励

给予方验收通过后，任务达成事实保留，约定主状态进入待兑现。需要补充时说明原因，执行者完善后重提。兑现方在线下兑现奖励，再在应用标记已兑现，流程即结束；接收方无需再次确认。

这是自 1.4.0 起采用的规则，替代旧版“已给出后等待收讫”的流程。旧版已给出、尚待收讫的奖励将显示已兑现，原给出记录以及已有收讫、分歧历史仍可查看，不会新增未发生的确认。家长代记来源继续如实显示。

## 修改、到期与退出

生效条款由一方提出修改，另一方同意后更新；确认前仍按旧条款执行。到期未提交需要先协商延期；按时提交后等待验收不会因对方处理慢而失败。

取消同样需要对方同意；已经达成的任务不能取消来清掉奖励。解除关系停止新协作，已有共同历史和待兑现奖励保留。奖励由兑现方整体标记兑现，首版不支持分阶段兑现。

## 连接失败时

输入不会因为一次连接错误就算提交成功。保留当前页面重试；遇到版本冲突先刷新，核对对方刚完成的操作后再决定。登录失效需重新登录；退出账号不会删除服务端记录。

首版是本地开发预览：不含系统后台推送、找回密码、在线支付或云端自动备份。记录保存在所连接的服务端，调试账号不要使用真实家庭资料。
