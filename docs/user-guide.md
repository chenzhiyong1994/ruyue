# 如约 使用说明

本页说明当前开发预览的使用路径。先按[开发指南](development.md)启动本地服务并构建客户端，两位用户连接同一服务；验证入口与边界见[测试指南](testing.md)。

当前客户端版本为 1.2.3，关系范围入口位于“我们”页。相同包名与签名的版本覆盖升级保留原有账号、关系和约定记录。

## 先建立关系

各自注册账号，设置自己的昵称。一方在“我们”页创建亲子、情侣或自定义关系，将邀请口令私下交给对方；对方加入后才能提出约定。邀请过期可重新生成。自己的关系称呼可以修改，不会改写对方身份。

孩子没有自己的账号时，选择家长代记，填写孩子称呼。该模式由家长记录，不把家长操作显示为孩子独立同意。孩子有独立账号时使用双方协作关系。

## 找到现在要做的事

日常页展示一份重点约定、下一步行动和奖励期待，下方用文字汇总待接受、待完成、待验收、我该兑现、等对方兑现 / 待收讫。可以打开重点约定，或通过“查看全部约定”进入约定页。

默认查看全部关系。拥有多段关系或已有范围选择时，“我们”页“每一段我们”标题旁会显示“查看范围”。点击后选择关系，再点“应用范围”，日常、约定、奖励和我们四页会共同使用该范围；点击“返回”取消本次选择。选中的关系会在“每一段我们”下方提示，再次进入“查看范围”可恢复“全部关系”。

约定页和奖励页可以通过“筛选状态”下拉框查看对应记录；奖励页区分我该兑现、等对方兑现、待收讫和已兑现。解除关系后，已经产生的奖励仍会保留。查看详情后，点击页面上的“返回列表”回到列表。顶部同步信息只在同步中或有反馈时出现。

## 把约定说清楚

选择“创建约定”，分三步填写：先选已建立的关系并说清标题、达成条件、次数和截止，再填写奖励与兑现天数，最后核对完整条款及双方角色。提出者负责验收与奖励兑现，关系中的另一位负责执行；想交换角色时由对方发起新的约定。一次性事项目标次数为 1；累计目标填写总次数。完成截止可以不限期。上一步会保留输入；在最后一步可“存为草稿”或“发出约定”。发出后需等对方接受，对方也可以拒绝。

对方接受后，执行者记录进度，完成时添加说明或照片并提交。累计目标先完成全部次数，再统一提交验收。照片只供此约定有权成员查看。

## 验收与奖励

给予方验收通过后，任务显示已达成，奖励进入待兑现。需要补充时说明原因，执行者完善后重提。给予方在线下兑现奖励，再在应用记录已给出；接受方真正收到后确认，约定才全部完成。

“奖励待兑现”和“已给出，待收讫”不是同一个状态。如果尚未收到，选择反馈尚未收到并留下说明，记录继续保留。家长代记关系完成时显示代记来源。

## 修改、到期与退出

生效条款由一方提出修改，另一方同意后更新；确认前仍按旧条款执行。到期未提交需要先协商延期；按时提交后等待验收不会因对方处理慢而失败。

取消同样需要对方同意；已经达成的任务不能取消来清掉奖励。解除关系停止新协作，已有共同历史和待兑现奖励保留。奖励整体收到后才结清，首版不支持分阶段领取。

## 连接失败时

输入不会因为一次连接错误就算提交成功。保留当前页面重试；遇到版本冲突先刷新，核对对方刚完成的操作后再决定。登录失效需重新登录；退出账号不会删除服务端记录。

首版是本地开发预览：不含系统后台推送、找回密码、在线支付或云端自动备份。记录保存在所连接的服务端，调试账号不要使用真实家庭资料。
