# 如约 产品需求 v1.1

本文规定开发预览的产品范围与预期行为，不将规范本身视为验证结果。当前客户端版本为 `1.2.3` / `versionCode 6`；运行方法见[开发指南](development.md)，验证入口与边界见[测试指南](testing.md)。

## 产品目标

让亲密关系双方把答应的事说清楚，并共同完成：建立关系 → 提出约定 → 对方接受 → 执行与提交 → 验收达成 → 奖励给出 → 收讫确认。任务达成和奖励兑现独立记录，全部完成才算约定履行完毕。

## 首版范围

- 安卓优先；两名真实账号可以分别使用设备，服务端保存共享状态。支持亲子、情侣、自定义两人关系，一人可以有多个隔离关系。
- 无独立设备的孩子由家长建立档案并代记，所有相关动作和结案显示代记来源，不冒充孩子独立确认。
- 一次性任务与累计目标共用约定对象。累计目标记录进度，达到目标后统一提交验收。每条约定一名执行者、一名验收及奖励给予者、一份整体兑现的奖励。
- 约定含标题、验收条件、完成截止（可不限期）、目标次数、奖励描述、达成后的兑现天数。默认 1 次、7 天兑现，用户可修改。
- 草稿、发布、接受/拒绝、记录进度、文字/图片提交、退回补充、验收、奖励给出/收讫、协商修改、取消、关系解除和事件历史。
- 四个入口：首页待办、约定、奖励、关系。支持关系/状态筛选；待兑现和待收讫必须突出可见。
- 首版提醒为应用内待办与逾期提示，打开或刷新时同步。后台系统推送是后续能力，不将应用内提醒描述成推送。

## 硬规则

1. 发布不等于生效，对方接受后开始；角色按约定确定，不固定关系中的上下级。
2. 生效后的条件、期限、奖励不得单方改写。变更提案经另一方确认才生效，旧内容和操作人可追溯。
3. 及时提交后等待验收，不因审核延迟变成失败。超期未提交标记到期，延期经双方确认后才能继续。
4. 验收通过产生奖励待兑现；给予方表示已给出后仍等待接受者确认。未收到可以提出分歧，不能单方结清。
5. 到期、归档、关系解除均不抹除已产生的奖励。达成后的普通取消被拒绝；奖励替换须接受者同意。
6. 家长代记关系可以由家长完成流程，但显示“家长代记已结案”，与双人确认区分。
7. 关系解除停止新增约定与普通互动；双方可以查看已有共同记录并处理既有奖励结算。新关系不会获得旧关系权限。
8. 奖励在应用外给付；首版不接入支付、积分商城、陌生人任务市场、自动惩罚、公开排行或 AI 裁决。

## 体验与信息结构

日常首页围绕当前关系的一份重点约定、下一步行动及奖励期待展开，并以文字汇总待接受、待完成、待验收、我该兑现、等对方兑现 / 待收讫。约定详情呈现当前状态和主行动、完整条款、进度、证据、奖励状态及事件时间线；每种身份只显示有权执行的动作。“我们”页支持创建、邀请、加入、修改自己的关系称呼及解除。约定与奖励页使用状态下拉筛选，详情提供“返回列表”。

四页默认查看全部关系，顶部不常驻关系筛选栏。关系数量大于 1 或已有关系筛选时，在“我们”页“每一段我们”标题旁显示轻文字入口“查看范围”；点击后在弹窗中选择关系并点击“应用范围”，返回取消不改变选择。查看范围仍由四页共享，选中的关系在该节现有副标题中说明；恢复全部也通过该入口。同步信息只在同步中或有反馈时显示，无消息时不占位。

项目界面约束：后续界面迭代或版本回退不得恢复四页公共顶部关系栏，实施前及验收时须对照本节与 PA-009。此规则只适用于如约 APP 的公共顶部关系栏，不禁止其他筛选。规则与实现仍须通过设备和视觉检查验证。

品牌为“如约”，视觉采用柔和渐变、珍珠暖白、玫瑰珊瑚、淡紫灰与交叠环线，成熟而有温度。首页、创建过程、详情与奖励反馈使用一致的层次与视觉语言。版本升级保留应用包和存储身份，兼容已建立的约定；窄屏、大字体、状态可辨认与单手操作须验证。实际界面示例见[项目说明](../README.zh-CN.md)。

创建使用全屏三步：选择关系并填写目标与截止 → 约定奖励及兑现时间 → 核对完整条款与双方角色。前两步只编辑本地表单，返回上一步保留输入；最后才发出约定或存为草稿。失败保留表单，同一内容重试沿用幂等身份。发出后必须等待对方接受，达到累计次数后仍需提交与验收。

示例均为合成数据：数学达到约定成绩后获得一次科技馆活动；本月共同运动八次后由对方安排一次晚餐。示例不自动写入用户账号。

## 验证与边界

验收见 [首版验收](acceptance.md)，状态与接口见 [共享契约](api.md)，技术与数据见 [架构](architecture.md)。真实用户试用、留存和付费证据尚未获得。重点观察首次双人闭环、奖励等待时间及再次创建约定，不能只统计任务完成数。

本地服务和调试 APK 用于开发验收；公网 HTTPS 服务、生产签名、账号找回、运维与商店发布需要单独落实，不能把本机双设备验证描述成已上线。
